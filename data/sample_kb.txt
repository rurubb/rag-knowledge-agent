LangGraph 知识库示例文档

LangGraph 是 LangChain 团队推出的有状态编排框架，专门用于构建多步骤、多智能体的 LLM 应用。它的核心抽象是 StateGraph：开发者把节点（普通 Python 函数）和边（可选的条件转移）组合成一张图，由 LangGraph 负责状态的流转、持久化和并发控制。

条件边（Conditional Edges）是 LangGraph 最关键的特性之一。普通边只把控制权无条件地从源节点交给目标节点；而条件边接收一个路由函数，该函数读取当前状态并返回一个字符串，决定接下来走哪个节点。例如在自反思 RAG 中，"评分"节点之后用一条条件边：若相关文档数为 0 且未达到重试上限，则路由到 "重写查询" 节点；否则路由到 "生成" 节点。

StateGraph 要求显式声明状态类型，通常使用 TypedDict。每个节点函数接收 state、返回一个 dict，LangGraph 会把返回的 key 合并回全局状态。这种"纯函数 + 状态合并"的模型让图的执行可重现、可回放，也便于单元测试。

LangGraph 内置了 checkpoint 机制，支持将中间状态持久化到内存、SQLite 或 Postgres，从而实现断点续跑、人机协同（human-in-the-loop）以及时间旅行（从历史某个 checkpoint 重新执行）。

检索策略方面，朴素 RAG 只做一次向量相似检索然后直接生成答案，召回率低且容易产生幻觉。工程化的做法是引入"反思"：先用 LLM 对每条召回文档打相关/不相关标签（grading），过滤掉无关片段；若全部文档都被判为不相关，则重写查询（query rewriting）后重新检索；生成之后再做一次幻觉检查（hallucination check），确认答案确实由召回文档支撑，否则回到重写查询环节。这种 retrieve → grade → rewrite → retrieve → generate → hallucination_check 的闭环就是 Corrective RAG (CRAG) 的核心思想。

Embedding 选择上，本项目默认使用 BAAI/bge-small-zh-v1.5 这个中文友好的本地嵌入模型，可以完全离线运行。也支持通过 OPENAI_EMBED_BASE_URL 切换到任意 OpenAI 兼容的 embedding API。

Chroma 是一个轻量级、本地持久化的向量数据库，适合中小型知识库的快速原型与生产部署。它在磁盘上以 SQLite + DuckDB 的形式存储集合与索引，首次 ingest 之后无需重新嵌入即可被后续的 ask 命令复用。
