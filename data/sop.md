# 客服操作 SOP（Standard Operating Procedure）

> 本文件为电商客服日常操作的标准流程（SOP），作为客服 Agent 检索"操作 SOP"知识库的核心数据源。客服在处理工单、投诉、退款、升级等任务时，应严格按本 SOP 执行。

## 一、工单受理流程

### 1.1 接待开场白

接到用户咨询后 30 秒内发送开场白：

> 您好，我是平台智能客服，工号 {{agent_id}}，很高兴为您服务。请问您遇到的具体问题是什么？

如用户情绪激动或表达投诉意图，应切换至安抚话术：

> 感谢您的反馈，我非常理解您的心情。我会尽快协助您解决，请提供订单号 / 商品链接 / 手机号以便核实。

### 1.2 问题分类与登记

按用户描述，将工单归入以下 6 大类别之一：

| 类别 | 触发关键词 | 处理人 |
|------|-----------|--------|
| 订单咨询 | "怎么下单" / "找不到订单" | 一线客服 |
| 物流咨询 | "怎么还没到" / "查物流" | 一线客服 |
| 退换货 | "退货" / "换货" / "退款" | 退货专员 |
| 投诉 | "投诉" / "差评" / "维权" | 投诉专员 |
| 账户安全 | "盗号" / "异常登录" | 安全专员 |
| 其他 | 不属于以上类别 | 一线客服 |

工单标题应包含：[类别] + 订单号 + 用户简述。例：`[物流咨询]NO2024xxxx-未收到货`。

### 1.3 信息核实

工单登记后，按以下顺序核实信息：

1. 订单号 / 用户 ID（必填）；
2. 商品 SKU、价格、商家 ID；
3. 物流公司、运单号、签收时间；
4. 用户诉求与期望方案（退款金额 / 重新发货 / 道歉赔偿等）；
5. 历史沟通记录（避免重复询问）。

信息不完整时不得擅自推进流程，应先索取缺失字段。

## 二、投诉处理流程

### 2.1 投诉分级

根据用户情绪、影响范围、潜在损失，将投诉分为 3 级：

- **L1（普通投诉）**：单一用户问题，金额 < 500 元，无媒体曝光风险。一线客服直接处理，48 小时内闭环。
- **L2（重要投诉）**：金额 500-5000 元，或用户表达曝光 / 维权 / 起诉意图。一线客服受理后 **2 小时内升级至投诉专员**，专员 12 小时内闭环。
- **L3（重大投诉）**：金额 > 5000 元，或已发生媒体曝光、群体投诉、监管部门介入。专员受理后 **1 小时内升级至投诉主管 + 法务**，主管 6 小时内向用户出具正式回应，并报备总经理。

### 2.2 处理话术

L1 投诉标准话术：

> 感谢您的反馈，已为您登记工单 {{ticket_id}}。我会立即核实并跟进，48 小时内给您答复。如急需解决，您可回复"加急"，我会按 L2 升级处理。

L2 / L3 投诉必须使用安抚 + 升级话术：

> 您反馈的问题比较严重，已为您升级至投诉专员（L2）或主管（L3），工单号 {{ticket_id}}。专员会在 {{SLA}} 内主动联系您。如需立即响应，请拨打 400-xxx-xxxx。

### 2.3 赔偿标准

- **L1 投诉**：原则上仅退款 + 道歉，不额外赔付；特殊情况可申请 5-50 元红包。
- **L2 投诉**：除退款外，可补偿商品金额 5-15% 的红包（上限 500 元）。
- **L3 投诉**：由主管 / 法务按个案审批，可涉及现金赔付、礼品补偿、媒体回应。

任何超过 50 元的赔付必须经投诉主管书面批准（IM 转工单审批）。

## 三、退款操作流程

### 3.1 退款类型

| 类型 | 触发条件 | 时效 |
|------|----------|------|
| 仅退款（未发货） | 订单状态为"待发货"前 | 1 小时内到账 |
| 退货退款 | 商品已寄回并被商家签收 | 1-3 个工作日 |
| 平台介入退款 | 商家超时未处理 / 拒绝合理退款 | 3-7 个工作日 |
| 急速退款 | 用户为黄金及以上会员，退货物流显示揽收 | 提前垫付，0-1 小时到账 |

### 3.2 退款审核要点

退款审核必须按以下顺序确认，缺一不可：

1. 订单状态是否符合退款类型要求；
2. 退款金额计算正确性（含原金额、运费、优惠券分摊）；
3. 用户是否已寄回商品（退货退款类）；
4. 是否触发风控规则（如同 IP 多账号退货、高频退款用户）。

任一项不符的，**不得通过**，应退回上一节点或转风控。

### 3.3 急速退款开通条件

满足以下条件之一可享受急速退款：

- 会员等级 ≥ 黄金；
- 历史信用分 ≥ 90；
- 单笔退款金额 ≤ 200 元；
- 商品类别不属于高风险类（如数码、奢侈品、虚拟商品）。

不满足条件的退款按常规流程处理，**不得擅自开启急速**，否则由客服个人承担风险损失。

## 四、升级与转接流程

### 4.1 升级触发条件

一线客服遇到以下情况必须升级（不得自行处理）：

1. 涉及金额 > 500 元的退款 / 赔偿；
2. 用户明确要求"主管 / 经理"对接；
3. 投诉 / 索赔金额超过 L1 标准；
4. 涉及法律、监管、媒体、公关风险；
5. 跨境 / 海淘类退款（因政策复杂）；
6. 风控拦截、账号封禁、资金冻结。

### 4.2 升级路径

升级须按以下路径逐级流转，不得跨级：

```
一线客服 → 投诉专员 → 投诉主管 → 客服经理 → 总经理
```

每级流转需在工单系统填写：升级原因、已处理事项、待处理事项、用户期望方案。升级后原客服须保持工单可见，跟踪直至闭环。

### 4.3 转人工时机

智能客服 Agent 遇到以下情况必须主动转人工：

- 用户连续 3 轮表达"听不懂 / 找人工 / 接人工"；
- 用户问题在知识库中检索 confidence < 0.6（参见 confidence 模块）；
- 涉及投诉、维权、法律、媒体等高敏场景；
- 涉及账户安全、资金冻结、风控等高风险场景；
- 用户情绪激动，明确表达不满 / 投诉 / 差评意图。

转人工话术：

> 抱歉，您的问题需要人工客服进一步处理。已为您转接工号 {{agent_id}}，预计等待 {{wait_time}}，您也可以留下联系方式，客服上线后第一时间回复。

## 五、知识库维护流程

### 5.1 知识库更新触发

以下情况客服需提交知识库更新申请：

1. 单日被问及超过 5 次且知识库无明确答案；
2. 政策 / 规则发生变更；
3. 出现新业务场景（如新支付方式、新会员等级）；
4. 检索结果长期低 confidence 的领域。

### 5.2 更新审批

知识库更新必须经"客服经理 + 业务方"双签确认，2 个工作日内完成审核：

- 通过：合并到主知识库，新版本立即生效；
- 驳回：附驳回理由，由原提交人修订后重新提交。

### 5.3 灰度发布

涉及核心流程（如退款规则、保修政策）的变更，须按"10% → 50% → 100%"灰度发布，每阶段观察 24 小时，无异常再扩大流量。
